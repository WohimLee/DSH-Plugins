# 团队分工

## 岗位与决定

| 岗位 | 负责的判断与交付 |
| --- | --- |
| 产品负责人（用户） | 确定目标、优先级、重要体验取舍及对外发布授权。 |
| 主理 Agent | 通过工作清单顶部的固定统筹入口统一接收、查重和规划需求。按交付分配负责人、分支与 Worktree，协调依赖、集成和 Desktop 验收，核对清理。需要产品决定时，带上选项及影响。 |
| 交互设计师（UX） | 在改变用户流程前明确入口、操作顺序、反馈和异常恢复，把验收场景交给研发。 |
| 界面设计师（UI） | 确定布局、状态样式及不同窗口下的表现，将视觉依据交给前端，并走查实现。 |
| 前端工程师 | 实现界面与宿主插槽的集成，自测交互，并通过实际入口验证改动。 |
| 模型接入工程师 | 实现认证、模型目录和推理协议适配，验证连接、取消、断开等受影响行为。 |
| 质量工程师（QA） | 明确验收场景，按用户入口复验，记录证据、可复现的缺陷和待验项。 |
| 安全审查人员 | 凭据存储、传递或访问边界变化时，审查凭据流向、日志及解绑后的处理。 |

岗位可随任务扩展。同一 Agent 可兼任多个岗位，同一岗位也可由多个 Agent 分担。需要独立审查或复验时，交给未参与该项实现的 Agent，并在结果中注明实际验证者。岗位分派沿用[仓库授权边界](../AGENTS.md#工作边界)。

## 本次任务由谁负责

接收需求的会话先登记到[共享工作清单](work.md)，主理 Agent 按最终交付物指定一名负责人。负责人可以由原会话、插件维护人或合适的专业岗位担任。涉及多个交付时，主理 Agent 另行明确集成和 Desktop 安装由谁执行。维护人提供插件历史与兼容信息。

任务负责人明确验收条件，约定各参与者的交付物，跟进到完成或记录具体阻塞。需交接的工作登记在[工作清单](work.md)。
