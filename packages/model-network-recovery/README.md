# Model request network recovery

Codex Desktop, OpenAI API and Grok embed this shared Host code in their own tarballs. It is not an installable plugin and has no runtime workspace dependency. The consumers are maintained and validated together in this workspace; a submodule would split one contract across repositories without a separate ownership or upstream boundary.

A provider may emit `MODEL_CONNECTION_FAILED` only from the model request's connection-establishment boundary, when trusted transport facts show temporary DNS failure or network/host unreachable. HTTP status, TLS/configuration failures, generic timeout and body/SSE failures do not qualify. A provider must not opt in if a previous generation or tool operation may still be active. Do not infer request delivery from SDK prose or local IPC state.

The `agent/request-error` handler owns only this failure code on an explicitly registered route. It waits 5, 10, 20, 40 and then 60 seconds between attempts, checks a 10-minute wall-clock deadline before handing control back for another retry, and delegates other failures to the host's ordinary policy. It uses native retry events under a distinct policy key. Cancel, route removal and plugin teardown stop the wait. The deadline caps waiting for network, not the host's request preparation or the duration of an already approved attempt. A process-local permit ties retries to the original route generation and, where a local login can change in place, to its account identity. The helper does not send requests, switch providers, or rerun tools.

Qoder SDK 1.0.59 and DSH 0.2.2-rc.5's DeepSeek Messages adapter do not expose a safe model connection-stage result. They keep existing finite recovery. The named DeepSeek API route and native routes can opt in once the official adapter exposes a phase-aware transport seam or equivalent structured failure. The Qoder SDK must also guarantee completion of old-session cleanup and distinguish model delivery from daemon/control IPC.

Consumer regression tests use synthetic responses in the real Agent Loop, including a completed tool before a failure, mixed ordinary and network retry budgets, deadline expiry, and cancellation. Native schedule and chat both use the same automatic recovery. The current host's generic retry row shows the connection reason in expanded details; manual Continue is subject to host eligibility, and pure scheduled turns are not eligible.
