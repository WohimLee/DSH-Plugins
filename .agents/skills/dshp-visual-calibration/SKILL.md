# 插件界面视觉校准

## 定范围与基准

- 用户要求先记录时，在原任务逐条记下页面、组件、触发状态和观察到的偏差，等实施指示。已有授权的小修直接使用可确认的参考。
- 记录参考来源和版本，选用同类元素、同文案和同状态。记录会影响结果的窗口宽度、缩放、设备像素比、主题、字体及宿主文字设置。外部界面参考用于当前条目的尺寸、密度或交互比较，最终设计以本任务确认的目标为准。
- 定义逐项验收值或可观察结果与适用容差。能从参考测得的值和 DSH 实际计算样式分别记录。截图像素按设备像素比换算，字形边界记录为截图测量值。只有局部参考就先验有证据的项目，缺同文案或同状态样本的项目标待验。

## 实现与回归

- 在改前先复现偏差，核对实际渲染、宿主偏好和样式继承。定位拥有该行为的插件或宿主扩展点，按组件与状态调整，复用已有令牌和原生组件。
- 整体尺寸和内部边界分别量。例如 Workbench 侧栏总宽可能正确，图标栏仍偏窄。对文字偏差同时检查字号、行高和实际字形，需要时比较多行间距。相邻区域可有不同排版，例如改动文件列表和悬停 diff。
- 用所属插件的[宿主测试](../../../docs/testing.md#界面视觉校准)锁定稳定约束。按影响选择长文案、窄窗、展开收起、悬停、深浅主题或用户偏好。正文曾受日常 Desktop 的 15 px 宿主文字设置影响，复现时把该设定带入隔离测试。可以复现时先在旧候选验证用例确实失败，再验证修复。

## 交付证据

用同一条件保留改前、改后与必要的参考截图，按条目记录。测不出的字段用观察结果或待验原因填写。简单改动用本表的一行即可。

交付 Desktop 运行产物时，按[本机桌面交付](../../../docs/development.md#本机桌面交付)用同一已验证 tarball 更新，并从原入口实测改动状态。记下宿主版本、包版本和构建标识，分别记录隔离结果、真实 Desktop 结果和待验项。遵守当前任务的安装安排。
