# 独立管理开发基线和插件宿主范围

状态：implemented

## 问题

Desktop 从 DSH 0.2.2-rc.3 升到 rc.5 后，已安装插件的精确 `engines.dsh` 声明阻止了加载。DSH 用运行时版本判定第三方插件兼容性，桌面桥接协议版本与插件清单格式版本不参与此判定。

## 决定

根依赖与脚手架采用选定的精确开发基线。常规检查验证仓库内部一致性，迁移时显式与实际 Desktop 对比。插件发布包按宿主契约和同包跨版本验证选择有界范围。保留精确发布基线会让每次 Desktop 升级都触发换包，版本豁免只适用于个别已装版本且无法提供兼容证据。

当前范围为 `>=0.2.2-rc.4 <0.2.3-0`，依据 rc.4 和 rc.5 真实宿主验证，以及两版对插件所用扩展点的兼容。范围接受后续 0.2.2 预发布版与正式版，维护者在新版本可用时复用已有产物验证。实测记录逐版保存。

## 影响与验证

开发基线迁移到 rc.5。三个插件的同一组 tarball 在 rc.4 和 rc.5 的隔离 Web 宿主通过安装和相关测试。使用 rc.4 安装后，现有 profile 在 rc.5 启动成功，依赖声明和锁文件保持一致。macOS Desktop rc.5 已通过内置 CLI 同名更新 Codex 和 Workbench，验证插件启用、工作台功能栏和 Codex 模型分组。真实账号推理待验收。
